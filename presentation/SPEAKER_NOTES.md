# Текст доповіді для захисту семінарського проєкту «FoodScan AI»

## Слайд 1. Титульний
Доброго дня! Тема мого проєкту — **«FoodScan AI: Вебсервіс для аналізу складу харчових продуктів за штрихкодом та оцінки їхньої корисності»**. У рамках роботи було обрано хмарний AI API, розроблено робочий Proof-of-Concept вебсервіс на Python (FastAPI) та підготовлено репозиторій на GitHub.

## Слайд 2. Актуальність та постановка задачі
Сучасні споживачі щодня стикаються з великою кількістю ультраоброблених продуктів, де склад зазначений дрібним шрифтом із використанням індексів E-добавок та прихованих форм цукру. Мета проєкту — дати користувачу зручний інструмент, який за штрихкодом або текстом етикетки миттєво пояснює склад простою мовою та оцінює корисність продукту за 100-бальною шкалою.

## Слайд 3. Вибір хмарної платформи та API
Серед розглянутих хмарних платформ (Google Cloud, Microsoft Azure, AWS) для реалізації PoC було обрано **Google Cloud Platform — Generative Language (Gemini) API** (модель `gemini-2.5-flash`).
Причини вибору:
1. Нативна підтримка **Structured JSON Output** (`responseMimeType: application/json`), що дозволяє інтегрувати відповідь мовної моделі безпосередньо у backend без складного парсингу тексту.
2. Висока якість аналізу україномовних текстів та нутриціологічної термінології.
3. Швидка інтеграція та наявність безкоштовного рівня квот для тестування.

Для отримання фактичних даних про товари за штрихкодом використано **Open Food Facts REST API v2** — найбільшу у світі відкриту базу харчових продуктів.

## Слайд 4. Технічний опис API
Вебсервіс взаємодіє з двома зовнішніми REST API:
- **Open Food Facts API v2**: `GET /api/v2/product/{barcode}.json` — повертає назву, бренд, інгредієнти, таблицю поживної цінності на 100 г, теги харчових добавок, алергени, рейтинг Nutri-Score та групу обробки NOVA.
- **Google Gemini API**: `POST /v1beta/models/gemini-2.5-flash:generateContent` з передачею ключа в заголовку `x-goog-api-key`. Модель отримує структуровані дані про продукт і повертає JSON із балом корисності (0–100), вердиктом, перевагами, ризиками, розбором E-добавок і порадою споживачу.

## Слайд 5. Сфери застосування API
Окрім персонального контролю харчування (HealthTech), використаний підхід та Gemini API мають широке застосування у:
- **E-Commerce та ритейлі** — автоматичне формування дієтичних тегів товарів і рекомендація здоровіших альтернатив;
- **Фармацевтиці та косметології** — аналіз складу косметики (INCI) та дієтичних добавок;
- **EdTech** — інтерактивні освітні асистенти;
- **Корпоративній автоматизації** — перетворення неструктурованих описів та документів у валідний JSON.

## Слайд 6–8. Архітектура PoC та результати тестування
Проєкт побудовано на асинхронному фреймворку **FastAPI** із використанням бібліотеки `httpx` та валідації `Pydantic v2`. Реалізовано механізм відмовостійкості: якщо API-ключ не задано або виникає мережевий збій, вмикається локальний нутриціологічний рушій, який розраховує оцінку за критеріями ВООЗ.
На тестуванні сервіс коректно розрізнив висококалорійні продукти з надлишком цукру та насичених жирів (Nutella — 26/100, Coca-Cola — 24/100) від збалансованого цільнозернового хліба (86/100).

## Слайд 9–10. Безпека та висновки
API-ключ ізольовано у файлі `.env`, який виключено з Git-репозиторію через `.gitignore`. У майбутньому проєкт легко розширити функцією сканування штрихкодів камерою та розпізнаванням фото етикеток через мультимодальний Gemini Vision API. Дякую за увагу!
